# Versioned causal strategy profiles

D04 retains two explicitly named profiles, both version1. Configuration selects one; there is no result-driven profile selection. Existing dashboard namespaces/configurations without a profile field retain dashboard_intraday/version1; their immutable stored configuration is not rewritten. New versions/intents explicitly record the selected profile. Changing configuration does not change open holding rules or old intent provenance. Legacy signals without a new stable identity are not automatic execution commands; BT09 owns automation intake and remains disabled until its integration is complete.

These windows preserve the original runtime fetch lengths. The pure evaluator accepts a characterized shorter valid input with at least50trend bars and21bias/execution bars, using up to the profile's fixed windows. Runtime requires complete full windows. Replay BT10 must provision the same windows before the requested start, retain that coverage provenance and invoke this evaluator. Short-history fixture parity does not establish replay data coverage.

EMA uses pandas ewm(span,adjust=False), seeded by the first close in the selected window. RSI uses simple14-bar rolling means of gains/losses; a zero loss is replaced by1e-12. Flat closes therefore retain the legacy zero-RSI outcome, rather than silently switching to Wilder RSI or a neutral50. Close pivots use a centered3-close window, equality extrema, then the last three highs and lows with strict increasing comparisons. The right-hand confirming close must already be completed. Pivots are never candle-high/candle-low pivots.

A bullish engulfing requires the previous body bearish, current body bullish and the current body inclusive of both prior body endpoints. Hammer requires a nonzero body, lower wick at least twice the body and upper wick no more than half the body; its close need not be bullish. Pattern priority is engulfing, hammer, then dashboard indicator entry. Dashboard bias thresholds come from the supplied immutable configuration (legacy defaults near0.02/RSI30, dashboard execution RSI45). The daemon_daily v1 bias retains its fixed0.02/30 independently of dashboard configuration; changing those requires a separately approved version change; no capital or financial setup value is introduced here.

For a bound held position, entries are suppressed and exits are evaluated first. Both profiles expose the configured take-profit/stop-loss reason using the separately observed quote and entry-bound rules. Dashboard then preserves ordered ema21_cross_down_15m, rsi_overbought_cross_down_15m, ema21_break_1h_rsi_down reasons. The daily profile adds no indicator exit. These are advisory strategy reasons: native/simulated protective execution belongs to BT07 and manual reduction still requires the guarded intent service. Unknown basis or unbound/mixed entry rules returns unavailable instead of invented rules.

Decision time is explicit and timezone-aware. All frames are independently aligned to UTC opens and their own close boundary at the last15m execution close. Only bars closed at or before that decision participate; future/forming OHLC changes are ignored before validating completed data. Gaps, duplicate/unsorted/unaligned timestamps, invalid OHLC/nonfinite values, stale latest close or insufficient history return an explicit unavailable state and no signal. A current UTC daily candle cannot authorize an intraday decision using its later final close.

Stable signal_id is a SHA256 over namespace,venue,profile,profileversion,configversion,symbol and execution-close milliseconds. Decision output time is that close, not scan wall-clock time. Repeated scans and restarts retain identity; a namespace/profile/config/symbol/candle change creates a different decision key. This does not authorize another automatic order: BT09 must use the durable intake idempotency boundary. Snapshot publication includes profile/version/config and explicit unavailable decisions; imports, HTTP requests and the evaluator perform no private transport.

Dashboard and daemon adapters read only explicit cached bars, prices, position/rule observations and config; both invoke the same pure evaluator. Runtime fetches the union of selected and entry-bound profile frames, retaining old position exit inputs after a profile change. A window change at the same candle refetches insufficient cache rather than reusing a shorter window. There is no evaluator network/database write, credential access, global-config dependency or automatic trade side effect.

Causal corrections from the characterized source are explicit: exclude forming/future bars; confirm centered pivots only with completed neighbors; suppress new-entry signals for an already-held position; use candle identity rather than wall time; report missing data instead of a valid no-signal; keep old bound exits after configuration changes. The mathematical indicator/pattern definitions remain unchanged. Original legacy indicator helpers remain characterization surfaces; production adapters use the shared evaluator.
