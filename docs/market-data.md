## Observation and validation

The public Spot adapter calls explicit REST methods, avoiding CCXT's implicit market/currency/private discovery. Testnet sandbox selection still precedes every request. Public paper data needs no private credentials. Endpoint costs are exchangeInfo plus server time (21 weight, 2 requests), all-symbol 24-hour tickers (80), selected tickers (2 for 1–20 symbols, 40 for 21–100, 80 above 100), and klines (2 each). These are endpoint costs, not invented IP limits. Actual REQUEST_WEIGHT/RAW_REQUESTS windows come from exchangeInfo; used-weight headers raise local usage when outside IP activity is reported. Separate per-account ORDERS admission/reconciliation belongs to BT06 and is excluded from this IP pool.

The server clock is measured with request round-trip bounds. Skew or uncertainty reaching the selected 60-second freshness bound prevents readiness. Public quotes are estimates with venue/symbol/fetched-at provenance, never exchange fill evidence. Failed refresh preserves value and timestamp, exposes failure and cannot freshen an expired quote.

The retained dashboard evaluator receives only completed bars: 200 four-hour bars, 200 hourly bars, and 100 fifteen-minute bars. Existing indicator/exit definitions remain; profile unification is BT08. Validate finite positive OHLC, OHLC ordering, nonnegative volume, aligned/sorted/unique timestamps, contiguous intervals, sufficient warmup and latest completed close. Discard the forming candle. Revalidate restored cache; reuse slow history until its next close. Entries are namespace/venue/symbol/timeframe qualified with each bar's opening timestamp and original fetched-at. New closes invalidate readiness until updated completed history exists. Missing/invalid cache triggers owned refetch/degraded status, never a fabricated fill.

Dynamic selection ranks current Spot/TRADING markets by quote volume with a stable symbol tie-break. Quote rules and UP/DOWN/BULL/BEAR exclusions apply. Static fallback is ETH, BTC, SOL and BNB in the configured quote, filtered against metadata, whitelist and blacklist; a previous quote's candidates never become the fallback. WHITELIST/BLACKLIST are comma-separated canonical BASE/QUOTE symbols; empty filters impose no restriction. Discovery filters never remove position, nonterminal intent or nonterminal protection coverage. Held/pending/protected symbols receive data first. Inactive/non-Spot/missing required markets cause an invalid-market failure.

## Readiness, configuration and failures

Authenticated `/api/status` exposes config version, owner state, heartbeat, last completed scan, coverage, skew/round trip, degraded reason, price provenance/age/freshness, and discovered request windows. HTML uses the same durable observation. Reads share one SQLite snapshot. Stopped/recovering ownership, unresolved outcomes, changed config, failed/old scans, missing newly completed history, failed/expired quotes and unavailable/backed-off budget cannot authorize a paper effect. Failure never advances last success. Abrupt scanner death loses readiness through price expiry and reports scan staleness by 600 seconds even when HTTP remains alive.

Configuration validation is complete and atomic: finite numbers, integral counts, positive/nonnegative ranges, fractional bounds, RSI bounds/order, canonical quote, strict booleans and optimistic versions. Omitted values remain unchanged; equity_proxy persists as the retained estimate. No D05 capital/fee/protection policy is selected. The saved trailing value is explicitly unavailable and implies no trailing order.

Advisory exits bind to the immutable entry config when the current holding cycle has one provable configuration. Closing a cycle clears that association for the next entry. Mixed entry configurations and migrated/unknown opening history expose `position_rules.state=review_required` and produce no guessed advisory exit. No FIFO/LIFO/lot policy is selected while D05 is unresolved, and a settings/quote change never rewrites known existing exit rules.

Failures are redacted rate-limit, auth, transient, invalid-market and data-quality classes. Provider payloads/credentials do not enter ordinary status. Retry-After is never shortened. Transient delay is exponential, bounded at 2–60 seconds plus under one second of jitter; rate-limit delay also includes the provider wait. Missed slots coalesce rather than causing catch-up bursts. Auth blocks persist across restart and require review. After reviewing access/configuration, stop the owner, run `python manage_state.py resume-market --actor <operator-id>`, and restart the scanner. Review is journaled; readiness remains degraded until a successful scan. This does not relax financial checks or authorize trading.

The declared public burst is metadata/time + largest ticker request + three candles per held/pending/protected symbol (101 + 6 per symbol weight; 3 + 3 per symbol raw requests, minimum one symbol). Maximum declared headroom persists across clients. Future private clients must declare larger known urgent bursts and use this interface. This is scheduling capacity, not a financial risk policy.

Use controlled Binance egress or route all cooperating clients through the pool. Headers reflect reported outside used weight; 429/418 still impose shared backoff. Offline fixtures do not prove provider acceptance or coordination of programs outside this architecture. ## Additive migration, backup and rollback

Fresh explicit `manage_state.py init` installs market_budget_v1. Existing BT03 stores require a reviewed stopped-owner `python manage_state.py upgrade-market`; opening/scanning never creates it or repairs financial state. The additive extension preserves financial schema v1 identity, immutable config, fills and journal effects. Repeating it is idempotent. Candles/health live in the existing scan snapshot. Whole-store backups include extension/cache; older candidates require explicit upgrade before scanning. Invalid existing settings remain a review gate and are never silently rewritten.

Keep current journal/backups; use compatible read-only readers on rollback. Never reactivate an executor predating these freshness guards. Actual migration, supervision, restore rehearsal, provider certification and deployment are separate gates; none was performed on existing account data.
